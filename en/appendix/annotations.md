# Annotations Cheat Sheet

Every sqltoy annotation lives in `org.sagacity.sqltoy.config.annotation` (23 in total) and falls into six groups: entity mapping, primary keys and business ids, associations, enterprise features, cache translate and DDL. This page lists each annotation's **target, attributes, defaults and purpose**; follow the links for detailed usage.

> Most POJOs are generated by [quickvo](en/prepare/quickvo.md) straight from database tables and arrive with the annotations filled in. Hand-written annotations are mainly used to adjust mappings, add DDL information such as `@Index`/`@Partition`, or attach enterprise features to existing entities.

| Annotation | Target | Purpose | Details |

## 2. Entity and column mapping

### @SqlToyEntity / @Entity

`@SqlToyEntity` has no attributes — it is a semantic alias of `@Entity`; both mark a class for entity scanning (`packagesToScan`).

| `@Entity` attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `tableName` | String | required | Database table name (without schema) |
| `schema` | String | `""` | Schema name, for multi-schema setups |
| `comment` | String | `""` | Table comment, written at table creation |
| `pk_constraint` | String | `""` | Primary-key constraint name, e.g. `PRIMARY` |

### @Column

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | String | required | Database column name |
| `type` | int | `java.sql.Types.OTHER` | JDBC type; with `OTHER` it is inferred from the Java field type |
| `nativeType` | String | `""` | Native type name (e.g. `varchar2(50)`, `jsonb`); takes precedence over `type` for DDL |
| `nullable` | boolean | `true` | Whether the column is nullable |
| `length` | long | `0` | Length (characters/bytes depending on the type) |
| `precision` / `scale` | int | `0` | Numeric precision and scale |
| `generatedType` | `GeneratedType` | `DEFAULT` | Generated column: `DEFAULT` (plain) / `VIRTUAL` / `STORED` |
| `keyword` | boolean | `false` | Whether the column name is a database reserved word (quoted by object operations) |
| `comment` | String | `""` | Column comment |
| `defaultValue` | String | `SqlToyConstants.DEFAULT_NULL` | Default value used in DDL; unset means no default |
| `autoIncrement` | boolean | `false` | Whether the column auto-increments (DDL) |

> `keyword=true` and the global `spring.sqltoy.reservedWords` are two different paths: the former handles quoting of that column in **object operations**, the latter makes **custom SQL** adapt reserved words per dialect. See [FAQ](en/faq/faq.md).

### @SqlToyFieldAlias

| Attribute | Type | Notes |
| --- | --- | --- |
| `value` | String | Target POJO property name; makes `convertType` map correctly when a VO and a POJO use different field names |

## 3. Primary keys and business ids

### @Id

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `strategy` | String | `assign` | `assign` (manual), `sequence`, `identity`, `default` (22 digits), `nanotime` (26 digits), `snowflake`, `UUID`, `ULID`, `redis`, etc. — same values as [Primary Key Strategies](en/primarykey/sqltoy_primarykey.md) |
| `sequence` | String | `""` | Sequence name for the `sequence` strategy |
| `generator` | String | `""` | Custom generator class (implementing `IdGenerator`); when set it wins over the built-in `strategy` |
| `isAssist` | boolean | `false` | Assist key: on partitioned tables the partition column must be part of the primary key, so mark it here (mysql, pg, etc.) |

### @BusinessId

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `signature` | String | required | Signature expression, supporting macros such as `@case(name,v1,then1,...)`, `@day(yyMMdd)`, `@substr(name,start,length)` |
| `generator` | String | required | Generator class, e.g. `org.sagacity.sqltoy.plugins.id.impl.RedisIdGenerator` |
| `length` | int | `-1` | Total business-key length; -1 uses the global setting |
| `sequenceSize` | int | `-1` | Trailing sequence digits; -1 uses the global setting |
| `relatedColumns` | String[] | `{}` | Associated columns whose values feed the generation |
| `start` | long | `1` | Initial sequence value |

> Only a **single** business key per table can be declared; for several, use `@BusinessId` plus `lightDao.generateBizId(...)` to assign them yourself. See [Primary Key Strategies](en/primarykey/sqltoy_primarykey.md).

## 4. Associations and cascades

### @OneToOne / @OneToMany

Both share the same attributes; `@OneToMany` adds `orderBy`:

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `fields` | String[] | `{}` | Main-table columns taking part in the association (empty means the primary key) |
| `mappedFields` | String[] | required | Corresponding columns in the child table |
| `delete` | boolean | `false` | Whether deleting the parent cascades to children |
| `load` | String | `""` | Filter applied when cascade-loading (e.g. `status=1`) |
| `update` | String | `""` | Cascade update control |
| `notNullField` | String | `""` | Field used for a not-null check |
| `orderBy` | String | `""` | `@OneToMany` only: ordering of the child collection |

> sqltoy supports **one cascade level only**; batch methods such as `loadAllCascade`/`updateCascade` are optimized with IN queries underneath, avoiding N+1.

### @Foreign

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `constraintName` | String | `""` | Foreign-key constraint name |
| `table` | String | required | Referenced table |
| `field` | String | required | Referenced column |
| `deleteRestict` | int | `1` | Delete referential action (`ReferentialAction`: CASCADE/RESTRICT/SET_NULL/NO_ACTION/SET_DEFAULT) |
| `updateRestict` | int | `1` | Update referential action, same values |

> Since 6.0.3 unsupported referential actions are trimmed per database compatibility. The `Restict` spelling is historical — do not "fix" it.

## 5. Enterprise features

### @Sharding and @Strategy

| `@Sharding` attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `db` | `@Strategy` | empty | Database sharding strategy |
| `table` | `@Strategy` | empty | Table sharding strategy |
| `maxConcurrents` | int | `10` | Shard parallelism: 0 unlimited, 1 serial |
| `maxWaitSeconds` | int | `-1` | Parallel wait limit (seconds) |
| `is_global_rollback` | boolean | `true` | Whether a single shard failure rolls everything back |

| `@Strategy` attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | String | `""` | Strategy bean name |
| `fields` | String[] | `{}` | Columns feeding the decision |
| `aliasNames` | String[] | `{}` | Field aliases (parallel to `fields`, for parameter alias scenarios) |
| `decisionType` | String | `""` | Decision type passed to the strategy (query/update/etc.) |

```java
@Sharding(db = @Strategy(name = "hashDataSource", fields = { "tenantId" }),
          table = @Strategy(name = "realHisTable", fields = { "bizDate" }))
```

### @Tenant

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `field` | String | `""` | Tenant column (database column name); when empty the convention/interceptor decides |

### @DataVersion

| Attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `field` | String | `""` | Version property name |
| `startDate` | boolean | `false` | Whether the version starts with a date (e.g. `202209231`) |

### @Secure / @SecureConfig

| `@Secure` attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `field` | String | required | Column to encrypt or mask |
| `secureType` | `SecureType` | `ENCRYPT` | `encrypt` (RSA) or a masking type: `tel`, `name`, `email`, `address`, `bank-card`, `id-card`, `public-account`, `discrete-rate`, `other` |
| `sourceField` | String | `""` | Source column for masking (e.g. taking characters from `staffName`) |
| `maskCode` | String | `""` | Replacement character, `*` by default |
| `headSize` / `tailSize` | int | `0` | Leading/trailing characters kept |
| `maskRate` | int | `0` | Discrete masking ratio (for `discrete-rate`) |

`@SecureConfig` has a single attribute `secures` (`Secure[]`) that attaches several `@Secure` rules to one entity.

## 6. Cache translate

### @Translate / @Translates

| `@Translate` attribute | Type | Default | Notes |
| --- | --- | --- | --- |
| `cacheName` | String | required | Cache name (the `cache` defined in `sqltoy-translate.xml`) |
| `cacheType` | String | `""` | Type inside the cache (e.g. dictionary category) |
| `cacheIndex` | int | `1` | Which result-set column matches the cache key |
| `keyField` | String | required | Property that receives the translated value |
| `split` | String | `""` | Separator for several keys in one column |
| `join` | String | `""` | Joiner for several translated values |
| `where` | String | `""` | Conditional translate: translate only when the condition holds |
| `uncached` | String | `""` | Placeholder emitted when the key is not found |

`@Translates` has a single attribute `value` (`Translate[]`).

## 7. DDL-related annotations

| Annotation | Required attributes | Notes |
| --- | --- | --- |
| `@Index` | `name`, `columns` | `isUnique` (default false), `sortTypes` (ASC/DESC per column) |
| `@Indexes` | `indexes` | Several `@Index` |
| `@Partition` | `strategy` | Partition strategy (RANGE/LIST/HASH/RANGE COLUMNS/LIST COLUMNS); `columns`, `expression`, `partitions` |
| `@PartitionDef` | `name` | One partition: `value`, `tablespace`, `endValue`, `endInclusive` (default true) |
| `@PartitionKey` | none | Marks the partition column; the partition-key hint for MPP table creation and DML |
| `@MppTable` | none (as needed) | `engine`, `engineArgs`, `keyModel`, `orderBy`, `distributedBy`, `buckets`, `properties` — the engine metadata of ClickHouse/Doris/StarRocks |

```java
@SqlToyEntity
@Entity(tableName = "sqltoy_order_info", pk_constraint = "PRIMARY", comment = "orders")
@Indexes({ @Index(name = "idx_order_staff", columns = { "STAFF_CODE" }),
           @Index(name = "uk_order_no", isUnique = true, columns = { "ORDER_NO" }) })
@Partition(strategy = "RANGE", columns = { "TRANS_DATE" }, partitions = {
        @PartitionDef(name = "p202601", endValue = "2026-02-01"),
        @PartitionDef(name = "p202602", endValue = "2026-03-01", endInclusive = false) })
public class OrderInfo implements Serializable {
    @Id(strategy = "default")
    @Column(name = "ID", type = java.sql.Types.VARCHAR, length = 22, nullable = false)
    private String id;
    // ...
}
```

## 8. Common combinations and caveats

- **Entity scanning**: either `@Entity` or `@SqlToyEntity` is enough. Without `packagesToScan` entities are loaded on first use; under **native** it is mandatory — see [GraalVM Native Image Guide](en/tools/graalvm_native.md);
- **`@Id` and `@Column` must both be present on a primary-key field**: `@Id` describes the generation strategy, `@Column` describes the column;
- **Leaving `@Column.type` as `OTHER`** (inferred from the Java type) is the least error-prone option; use `nativeType` when cross-database DDL needs precise control;
- **Composite keys**: annotate several fields with `@Id`; a lambda join update/delete then correlates through `LPK1…LPKn`;
- **DDL annotations (`@Index`/`@Partition`/`@MppTable`/`@Foreign`) only take effect when `autoDDL=true` builds tables or when `lightDao.tableApi()` generates DDL** — they do not affect runtime CRUD;
- **Enterprise annotations are declarations, not configuration**: `@Tenant`/`@Sharding`/`@Secure` all need the matching interceptor, strategy bean or provider; an annotation alone does nothing.
